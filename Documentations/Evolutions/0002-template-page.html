摘要

新增值类型 OBTemplatePage：一页欢迎页或 What's New 页要显示的东西（标题、正文、顶部图片、功能行）和它的版式（左右边距、功能行着色与间距、尺寸），全是数据。OBTemplateContainerViewController(page:primaryButton:secondaryButton:cancelButton:) 把它组装成模板视图、列表和容器控制器。调用方不再去设 templateType、needsExtraWideContent、preferredContentSize 这些视图和控制器的属性，也不必知道它们要在组装前还是组装后设。

要你定

已定

  1. 默认版式 .centered（App Store 的做法），随 0.2.0 发布，RuntimeViewer 改用页面值。

详细设计

公开接口 
public struct OBTemplatePage {
    public enum Image { case systemImage(String); case image(NSImage) }

    public struct Layout: Hashable, Sendable {
        public static let standard: Layout   // 175-point margins, image leads
        public static let wide: Layout       // 85-point margins, image leads
        public static let centered: Layout   // 68-point margins, image centered, rows 344 wide
        public static let privacy: Layout    // 68-point margins, content in an inner scroll view
    }

    public var title: String
    public var bodyText: String?
    public var image: Image?
    public var features: [OBTemplatePartBulletList.Item]
    public var featureTintColor: NSColor?
    public var featureSpacing: OBBulletListSpacing
    public var layout: Layout
    public var size: NSSize
}

extension OBTemplateContainerViewController {
    public convenience init(page: OBTemplatePage, primaryButton: Button,
                            secondaryButton: Button? = nil, cancelButton: Button? = nil)
}
  • 两个页面构造器：数组版与 result builder 版，默认 layout: .centered、size: sheetSize()。
  • 每次组装都新建视图与控制器；没有功能行时不建列表。
  • .image(_:) 走 initWithTitle:bodyText:icon:contentLayoutStyle:，图片按调用方给的尺寸显示（App Store 的 App 图标是 128pt）。

调研

动机与框架的版式规则

RuntimeViewer 的引导页三次「看起来不对」，每次都要在视图或控制器上补设属性，而且顺序有讲究：窗口 0 × 0（关自动约束、给尺寸），正文挤成约 130pt 一列（模板与列表都要设类型，模板第一次绘制才读类型，列表加行时就读间距）。用户比较样式后要求把组装这部分搬进库，封装成结构化数据。

  • 边距按 templateType：standard / unspecified 175pt（加宽 85），privacy、centered 68（-[OBTemplateView outerContentMargins]）。
  • 只有 centered 把顶部图片居中，文字一律按自然方向排。
  • 列表行宽：centered 344，其余 382 / 420（加宽 562 / 600）。
  • App Store 的 What's New 与欢迎页：模板与列表都 setTemplateType: 3，列表符号用 App 强调色；Freeform、Shortcuts 用 setNeedsExtraWideContent:。

替代方案

四条被否的路径
  • 版式用 enum：加一种版式就破坏调用方的 switch，改用 struct 加静态成员。
  • 直接暴露 templateType 与 needsExtraWideContent：把框架的组合规则交给调用方，改用具名版式。
  • 按钮也放进页面值：按钮带闭包，不是描述页面的数据；与已有构造器对称、作参数更顺手。
  • 页面值提供 makeViewController()：Apple 由值建控制器的先例多是控制器构造器，本包也已有 init(templateView:…)。

影响

  • 源码兼容：纯新增，已有接口不变。
  • ABI：不适用，本库以 SPM 源码分发。
  • 下游：RuntimeViewer 的 OnboardingPage+TemplateContainer.swift 可改为映射成 OBTemplatePage 再组装，等本包发布后抬下限。
  • 版本：新增公开类型，发布为 0.2.0。
