摘要

新建 swift-onboardingkit 包，给 macOS 私有框架 OnBoardingKit 提供两层接口。COnBoardingKit 是一份手写的 Objective-C 头文件：声明 27.2 SDK 的 OnBoardingKit.tbd 导出的全部 29 个类和 72 个隐私标识常量，成员取自 macOS 11.0 到 27.2 的运行时元数据，类型从框架代码里还原，整数参数换成本包命名的枚举，每个成员标上引入它的系统版本，部署目标 macOS 14。OnBoardingKit 是 Swift 层：功能列表用 result builder 写，容器的按钮用闭包代替 target/action 并自动对应新旧两套按钮，隐私页能 await 到关闭，模板视图有带默认参数的构造器。测试在运行时读取头文件，逐个核对声明的成员在当前系统上是否存在。

没有待定事项

范围（绑定加便利接口）与部署目标（macOS 14）已由用户选定。代码、测试与文档已作为新仓库的第一个提交进入本地 main，没有建远端。

提议方案

  1. 包结构照 swift-skylight：COnBoardingKit（Objective-C 头文件加一个空的 .m）与 OnBoardingKit（Swift），两个都是 product；macOS 14；Swift 6 语言模式。
  2. 头文件声明范围：.tbd 的 29 个类和 72 个常量；成员取 27.2 上存在的，不写实例变量、下划线方法、AppKit 方法的覆写，以及只服务于框架自身布局与缓存的属性和方法。
  3. 类型：按反编译结果写全 nullability、集合元素类型与 block 签名；只凭选择子字面意思定的标 [unverified]。
  4. 枚举：OBTemplateLayoutStyle、OBTemplateType、OBBulletListSpacing、OBDeviceType（NS_ENUM）与 OBBundleInclusionOptions（NS_OPTIONS）。名字由本包按行为起，并在注释里写明。
  5. 可用性：晚于 14.0 引入的成员标 API_AVAILABLE(macos(…))。
  6. Swift 名写在头文件的宏里：常量去掉 Identifier 后缀；OBPrivacyPresenter 的工厂改成 init?(splashFor:) 一族；OBPrivacyLinkController 基类的构造器和拼错的工厂方法在 Swift 里不可用。
  7. Swift 层四块：功能列表的 Item 与 builder；模板视图带默认参数和 features: builder 的构造器；容器按钮的 ButtonRole、Button、button(for:)、setAction(for:_:)；隐私页的 presentAsSheet(on:) async。
  8. 测试：一组测试在运行时读取头文件，逐个核对类、方法与属性存取器；一组测试覆盖 Swift 层。测试不把窗口放到屏幕上。

非目标

  • 不覆盖 iOS 版 OnBoardingKit（OBWelcomeController 等，Catalyst App 用的那套），也不覆盖 Welcome.framework。
  • 不声明 OBProcessNameForPID、_OBLoggingEnabled、_OBLoggingFacility：它们是框架内部的日志与进程工具。
  • 不包装 NSSymbolEffect 那组接口：Swift 造不出 NSSymbolEffect，包装了也没法用。
  • 不做 SwiftUI 包装：选定的范围是「绑定加便利接口」。
  • 不在 macOS 27.2 之外的系统上实测行为；旧系统只核对成员是否存在（来自元数据）。
  • 不建 GitHub 远端、不推送。

  • Item 的三个构造器按图片来源分（SF Symbol、自己的图片、无图），与 SwiftUI Label 的 systemImage: / image: 一致；有子项就成为可展开行。addItem(_:) 只在子项非空时才走 addExpandableItem…（框架收到空数组时什么都不加）。
  • 按钮的闭包收控制器作参数：关闭 sheet 时不必捕获控制器，避免循环引用。target 以关联对象挂在按钮上，因为 NSControl.target 是弱引用。
  • presentAsSheet(on:) 暂时替换 dismissHandler，sheet 结束时把原来的放回去、调用它，再恢复 await。

调研

动机与前期调研

动机

  • Apple 自己的欢迎页和 “What's New” 页用的就是这个框架。App Store、Freeform、Shortcuts 直接引用 OBTemplateView、OBTemplatePartBulletList、OBTemplateContainerViewController；Mail、Music、TV、Photos、Books 经 OBPrivacyPresenter 弹隐私页；Catalyst App 用的是 iOS 版的 OBWelcomeController。
  • SDK 里没有头文件。只有 OnBoardingKit.tbd；运行时元数据把对象参数记成 id、block 不带签名。
  • 框架本身很稳定。51 个版本（11.0 → 27.0）里 1246 个成员有 848 个从未变过，删掉的只有 24 个，多是内部辅助方法。
  • 直接调用有几处会踩空。按钮没有 target 和 action；隐私页没有 presentingWindow 就什么也不显示；模板视图在第一次绘制前没有子视图；fade… 的回调传 nil 会崩溃。

前期调研

  • 导出面：29 个类；72 个隐私标识常量；OBProcessNameForPID 与两个日志符号；一个 Swift 符号 NSImage.disclosureChevronImage(expandedState:)。没有 allowable-clients。
  • 成员与版本：演进接口文件给出 11.0–27.0 的存在位图；本机 27.2.1 运行时又少了三个：-[OBBundleManager orderedPrivacyBundlesWithPrivacyPaneBundle:] 与列表项的两个四参数构造器。
  • 类型与行为：在 27.2 归档 cache 上建了 OnBoardingKit.i64，逐个反编译并对照汇编。所有 block 都是 void (^)(void)；整数参数的取值见各枚举；容器的指定构造器是 first/second/link 那个，first = primary、second = cancel、link = secondary，按钮不接 target/action；OBPrivacyLinkController 的工厂返回 _macOS 子类；OBPrivacyPresenter.present 没有窗口时只记日志返回。
  • 实测：OBTemplateView 只在 viewWillDraw 之后才有子视图；可展开行的子项在 expanded = YES 之后才加进 expandableStack。
  • Swift 侧：NSSymbolEffect 标了 NS_REFINED_FOR_SWIFT；类型化常量不加 NS_SWIFT_NAME 时带着 Identifier 后缀导入。
  • 先例：swift-skylight 的 C target 加 unsafeFlags(["-F/System/Library/PrivateFrameworks"]) 加 @_exported import；tools 6.2 起依赖带 unsafe flags 的包不再被拒。

替代方案

七条被否的路径
  • 运行时查找代替链接。否：.tbd 导出了全部 29 个类，直接链接能得到编译期的类型检查。
  • 改名写进 apinotes。否：头文件是本包自己的，宏写在声明上读一处就够。
  • 一个 OBTemplateView 构造器包下四种来源。否：动画那条构造器自己决定 layoutStyle，合进去会让参数被悄悄忽略。
  • 最低系统 macOS 26。否：用户选了 14；旧构造器在 26 起照样能用，只需在取按钮时分版本。
  • present() async 与同步版同名。否：同名会让 async 上下文里的同步调用被换掉；等的是「关闭」不是「显示」。
  • 按钮闭包写成 () -> Void。否：最常见的动作是关掉 sheet，会逼调用方捕获控制器形成循环引用。
  • Swift 模块另起名。否：框架自身的 Swift 部分只有一个私有类和一个 NSImage 扩展，本包不定义同名符号；照 swift-skylight 用框架名。

影响

  • 源码兼容性：纯新增，新仓库没有既有调用方。
  • ABI：不适用，本库以 SPM 源码分发。对系统框架：声明与框架的选择子、参数位宽一致，换成枚举不改变调用约定。
  • 下游：暂无依赖方。
  • 文档：README（英文）、实现说明、本提案及网页版；没有示例 App。
  • 演进：系统删掉成员时 DeclarationPresenceTests 变红，再标 API_OBSOLETED 或删除；本包 Swift API 改名时保留旧名并标 renamed:；第一次打 tag 从 0.1.0 起。

落地步骤

  1. 骨架：swift build 成功，链接得到 OnBoardingKit.framework。
  2. 头文件主体与核对测试：Every declared class exists；Every declared method and property accessor exists；加回 27.2 已删的 makeDivider 时测试失败。
  3. 按反编译结果补类型、枚举与 Swift 名：swift-synthesize-interface 无警告，常量导入为 .appStore，工厂导入为 init?(splashFor:)。
  4. 功能列表 builder：顺序、条件与循环、状态行、可展开行、addItems 追加。
  5. 模板视图、容器按钮、隐私页：便利构造器、功能列表成为内容区、在容器里的层级；按钮标题与闭包、快捷键、替换动作、不持有控制器；presentAsSheet 关闭后返回并恢复原来的回调；工厂找得到系统的隐私页。
  6. 文档：README、实现说明、索引、本提案与网页版。

收尾判断：写了实现说明（声明来源、取舍规则、Swift 层依赖的框架行为）；调用方契约在 README 与头文件注释里，不另写使用指南；没有项目特有的新术语，不建术语表。
